# Концепция игры — Guess the Rule (v4)

## 1. Основная идея

Это Roblox multiplayer social deduction / party game.

На каждой карте есть набор возможных действий игрока. В начале раунда выбирается **секретное правило — определённая последовательность действий**, которую игроки не знают.

Например:

**Jump → Interact → Dash**

Игроки должны понять, какая последовательность является запрещённой, наблюдая за происходящим, экспериментируя и анализируя свои и чужие действия.

Если игрок выполняет точную последовательность, он получает **Rule Violation** и (при повторном нарушении) штраф.

Главная идея игры — не просто выполнять мини-игры, а постепенно **раскрывать скрытое правило**, пока другой игрок — Траитор — знает его заранее и пытается заставить остальных нарушить его. Игра построена как противостояние двух сторон — Investigators (все, кроме Траитора) и Траитор — по аналогии с Murder Mystery, а не как гонка за очками.

---

# 2. Система секретного правила

Правило представляет собой **строгую последовательность действий**.

Например:

* Jump → Interact
* Jump → Interact → Dash
* Jump → Collect → Climb
* Interact → Collect → Jump
* Jump → Interact → Dash → Collect

Если секрет:

**Jump → Interact → Dash**

то:

**Jump → Interact → Dash**

= нарушение.

---

# 3. Набор действий

Игра отслеживает действия из заранее определённого списка. Есть **базовый (универсальный) набор**, доступный на любой карте, и **уникальные действия конкретной карты** сверху него.

## Базовый набор

* Jump
* Dash
* Interact
* Collect

### Interact — единая механика для всех точечных взаимодействий

Открыть дверь, дёрнуть рычаг, починить что-то — всё это один и тот же Interact, независимо от объекта. Реализуется через ProximityPrompt с одинаковой подписью "Interact" на любом интерактивном объекте карты. Это держит список действий маленьким и не даёт пулу расти с каждым новым интерактивным объектом — а игроку визуально понятно, что это один и тот же тип действия, а не произвольная группировка на бэкенде.

### Collect — только сознательные, привязанные к квесту предметы

Через тот же принцип ProximityPrompt, не автоподбор на касание.

## Уникальные действия карты

### Карта "Лес" (текущая)

* Jump
* Dash
* Interact
* Collect
* Climb
* Push

### Карта B (пример)

* Jump
* Dash
* Interact
* Collect
* Swim
* Dig

Уникальные действия карты добавляются, если они хорошо вписываются в её окружение, и одновременно должны быть физически выполнимы где-то на карте как часть обычного прохождения (см. задачи, раздел 11).

---

# 4. Смена правила

Правило меняется не по фиксированному таймеру, а **по факту разгадывания**: как только кто-то из investigators верно угадывает текущую последовательность через Guess UI, правило сразу сменяется на новое, и начинается новый этап расследования.

Игрок, разгадавший правило, получает награду/очки и учитывается для звания MVP по итогам матча.

Если **N разных игроков** получили платное нарушение по текущему правилу без разгадывания — оно тоже меняется, но без разгадывания, и в наказание уменьшается общее оставшееся время раунда. Это не даёт Траитору просто "пересидеть" правило, которое никто не может разгадать, бесконечно долго — а инвестигейторам не даёт стоять на месте.

Каждая смена правила — это одновременно и прогресс к условию победы A (раздел 15), и сброс предупреждения/счётчика штрафов (раздел 12).

---

# 5. Как игроки узнают правило

Игрокам не показывается само правило.

Они должны самостоятельно его определить.

Основные источники информации:

### 1. Собственные нарушения

Игрок сделал несколько действий и получил:

**RULE VIOLATION**

После этого он пытается вспомнить, что именно делал перед нарушением.

Первое такое нарушение по текущему правилу — предупредительное: штраф не снимается, но сам факт нарушения показывается как обычно. Это превращает первую ошибку в бесплатный урок, а не в наказание, и напрямую поддерживает экспериментальный характер игры.

### 2. Наблюдение за другими игроками

Игрок может увидеть:

> Player A сделал Jump → Interact → Dash → получил нарушение.

Это может стать подсказкой для остальных. Соответственно все должны видеть, когда какой-то игрок получает нарушение — независимо от того, было оно предупредительным или платным.

### 3. Эксперименты

Игроки могут намеренно повторять подозрительные последовательности, чтобы проверить гипотезу.

Это важная часть gameplay loop:

**наблюдение → гипотеза → эксперимент → нарушение/отсутствие нарушения → новая гипотеза**

Наличие одного бесплатного нарушения на правило прямо поощряет эту механику: первый осознанный тест гипотезы ничего не стоит игроку.

---

# 6. История последних действий

Игроку не нужно постоянно показывать большую историю действий.

UI показывает каждое сделанное действие (которое входит в пул отслеживания) на короткое время (например, 3 сек), после оно исчезает. Также, можно добавить ограничение на максимальное количество отображаемых действий, если количество действий превышает это означает, самое старое пропадает, вне зависимости от времени.

Таким образом, если игрок хочет понять, почему получил нарушение, ему необходимо помнить собственную последовательность:

**Jump → Interact → Dash**

а не просто посмотреть её в UI.

Это также делает наблюдение за другими игроками важнее.

Также можно добавить, чтобы над другими игроками тоже показывалась их последовательность действий.

Отдельно в HUD должен быть небольшой персистентный индикатор состояния предупреждения по текущему правилу (например ⚠️ → 🚫 после использования) — чтобы игрок всегда понимал, есть ли у него ещё "бесплатная попытка" или нет.

# 7. Система угадывания правила

Игрок должен иметь отдельный UI для попытки угадать последовательность.

Пример:

```text
WHAT IS THE SEQUENCE?

[ ? ] → [ ? ] → [ ? ]

        [ GUESS ]
```

При нажатии на слот игрок получает список доступных действий **для текущей карты** (базовые + уникальные этой карты):

```text
Jump
Dash
Interact
Collect
Climb
Push
```

Он выбирает действия и их порядок.

Например:

```text
[ JUMP ] → [ INTERACT ] → [ DASH ]

              GUESS
```

Это позволяет сделать механику угадывания простой и понятной.

Не нужно вводить текст, использовать сложные формулировки или пытаться описывать правило словами.

Игрок буквально собирает предполагаемую последовательность.

Попытки угадывания ограничены **персональным кулдауном** (10-15 секунд, растёт с каждой следующей неверной попыткой), а не хардкапом на количество или экономическим штрафом. Кулдаун снижает эффективность бездумного спам-перебора комбинаций, но не выключает игрока из условия победы A целиком, пока он ждёт. Также используется цветовая подсказка по слотам: действие есть в правиле и на верном месте — зелёный, есть, но на другом месте — жёлтый, нет совсем — красный.

---

# 8. Траитор

В каждом раунде есть игрок-Траитор.

Траитор **знает текущее секретное правило**.

Но остальные игроки не знают, кто Траитор.

Основная задача Траитора — заставить других игроков случайно выполнить запрещённую последовательность **и/или дожить нераскрытым до конца матча** (см. условия победы, раздел 15).

При этом Траитор также может сам получить нарушение — и точно так же имеет одно бесплатное предупреждение на правило, как и остальные игроки. Отдельного исключения для Траитора нет, иначе отсутствие у него предупреждения само по себе стало бы подсказкой для его вычисления.

Траитор также участвует в голосовании за подозреваемого на равных с остальными (раздел 15) — это даёт ему дополнительный рычаг: размывать консенсус или переводить подозрение на невиновного.

---

# 9. Возможности траитора

Траитор должен иметь возможность влиять на игру через **геймплейные трюки**, а не просто говорить:

> "Сделай Jump, потом Interact."

Примеры механик:

### Fake Coin

Траитор создаёт или активирует привлекательный объект.

Например, монетка находится в месте, где для её получения игроку естественно нужно:

**Jump → Collect → Interact**

Игрок выполняет последовательность и получает нарушение.

### Fake Objective

Траитор может создать/активировать ложную цель, которая заставляет игрока выполнить определённые действия.

### Bait

Траитор создаёт ситуацию, в которой определённое действие кажется выгодным.

### Environment manipulation

В зависимости от карты Траитор может:

* временно закрыть дверь;
* изменить путь;
* активировать объект;
* создать препятствие;
* переместить/поставить интерактивный объект;
* заставить игроков изменить маршрут.

### Сокращение времени раунда

У Траитора есть способность (или несколько), позволяющая сократить оставшееся время раунда, повышая его шансы дотянуть до победы по времени. Такая способность должна быть заметной для остальных при использовании — она одновременно и рычаг силы, и потенциальная улика против него, а не невидимый читерский бонус.

---

# 10. Пример взаимодействия с Траитором

Допустим секрет:

**Jump → Collect → Interact**

Траитор знает правило.

Он размещает привлекательную монетку возле интерактивной панели.

Игрок видит монетку.

Он:

1. Jump
2. Collect
3. Interact

Получает:

**RULE VIOLATION**

Если это его первое нарушение по текущему правилу — штраф не снимается, но сам факт нарушения показывается, и он видит это как подсказку.

Игрок начинает думать:

> "Почему я получил нарушение?"

Он вспоминает свои действия и пытается найти закономерность.

Другой игрок мог увидеть это со стороны и тоже получить часть информации.

Так создаётся основная социальная дедукция игры.

# 11. Задачи и активность игроков

## 11.1 Общая философия

Задачи существуют не отдельно от механики правила — они создают ситуации, в которых игроки естественно оказываются в позиции для наблюдения, экспериментов, ловушек Траитора и случайных нарушений. Три требования к любой задаче:

* Быстрая и не требующая полного внимания — она фон, а не замена основной игре (дедукции/наблюдению/голосованию).
* По возможности завязана на тот же пул трекаемых действий, что и секретное правило (Interact/Collect через промпты, Jump/Dash по пути) — тогда выполнение задачи само создаёт материал для дедукции, а не существует в вакууме.
* Гоняет игрока между зонами, а не держит на месте — кросс-зонные задачи увеличивают шанс, что игроки пересекутся и увидят действия друг друга.

Задачи дают только XP/валюту (раздел 13) и **не являются условием победы** (раздел 15) — победу решают только разгадывание и голосование.

## 11.2 Персональные и повторяемые, а не общие на карту

Один и тот же тип задачи может выполнять несколько игроков одновременно и повторно за раунд — это основное правило, а не исключение. Технически: квестовые объекты (кусты с хворостом, сундук в шалаше, звонок на вышке) не блокируются и не расходуются, когда один игрок их использовал — они на персональном коротком кулдауне именно для этого игрока.

Это решает занятость лобби на 6-8 человек без необходимости придумывать десятки уникальных заданий: достаточно 4-6 повторяемых типов задач, размазанных по зонам, а вариативность приходит от того, в каком порядке и в какие зоны игрок сам решает идти — не от объёма уникального контента.

**Исключение** — разовые общие события на карту (не персональные): например, починка прохода в Руинах — кто первый сделал, открывает шорткат для всех до конца раунда. Такие события дают лёгкий социальный момент ("кто-то там что-то чинит, зачем?"), а не про занятость.

## 11.3 Награды и защита от квест-фарма

XP/валюта за выполнение, с **падающей отдачей за повтор одного и того же типа задачи одним игроком за раунд**: первое выполнение — полная награда, каждое следующее — меньше, до минимума. Смысл — не создавать доминирующую стратегию "фармить один и тот же квест весь раунд вместо участия в дедукции": раз задачи не решают исход матча, у них не должно быть причин конкурировать по выгоде с основной механикой.

## 11.4 Задачи по зонам карты "Лес"

Карта уже построена, 6 зон: Центр (Костёр), Роща, Вышка, Руины, Пруд, Шалаш.

* **Роща** — собрать N веток с кустов (Collect через prompt) → отнести к Костру (кросс-зонная доставка, форсирует Dash обратно к хабу). Отдельно — "проверь под упавшим стволом": повод исследовать зону, не завязан на конкретное трекаемое действие.
* **Вышка** — забраться (Climb) и подать сигнал сверху (Interact на площадке); либо "разгляди с вышки потерянный предмет внизу" — даёт игроку причину реально постоять на смотровой точке, которая и так стратегически важна для наблюдения за остальными.
* **Руины** — расчистить проход (цепочка Interact) — разовое общее событие на шорткат (раздел 11.2).
* **Пруд** — перейти на другую сторону (серия Jump по камням, либо Push плывущего бревна) и достать со дна предмет (Collect через prompt).
* **Шалаш** — открыть сундук внутри (Interact).
* **Центр (Костёр)** — не квестовая зона сама по себе, пункт сдачи для доставок из Рощи; необязательный декоративный Interact "посидеть у костра" — социальный момент без реальной механики, где игроки естественно скапливаются и видят друг друга.

# 12. Система нарушений и штрафов

За нарушение правила игрок получает **RULE VIOLATION**. Само событие всегда видно и ему, и остальным игрокам — это не зависит от того, штрафное оно или нет.

**Первое нарушение по текущему правилу — предупредительное.**
Оно показывается как обычное нарушение, но очки не снимаются. Это даёт каждому игроку один бесплатный, безопасный тест гипотезы на каждое новое правило.

**Начиная со второго нарушения по текущему правилу — штраф**, с эскалацией:

```text
1-е платное нарушение (по счёту 2-е нарушение всего): -50
2-е платное нарушение: -100
3-е платное нарушение: -200
4-е и далее: -200 (капается)
```

При смене секретного правила счётчик нарушений и статус предупреждения **сбрасываются полностью**.

Если **N разных игроков** получили платное нарушение по текущему правилу без разгадывания — правило меняется без разгадывания, а общее время раунда сокращается в наказание (раздел 4).

---

# 13. Награды за активность (XP/валюта — не влияют на исход матча)

Игрок получает XP/валюту за активность, но она **не является условием победы**:

* выполнение задачи: +XP/валюта, с падающей отдачей за повтор одного типа задачи (раздел 11.3);
* разгадывание правила: +XP/валюта, засчитывается в MVP (кто больше всего отгадал правил — MVP; в конце показывается лидерборд по XP/валюте за игру);
* выживание/завершение раунда: небольшой бонус.

Обычный сбор монет по-прежнему даёт валюту, но не проходит через систему трекинга действий (раздел 3) — это чистая экономика.

Смысл — дать игроку постоянную занятость и прогрессию даже тогда, когда он ещё не готов активно участвовать в дедукции, без риска, что матч можно выиграть просто фармом активности в стороне от основной механики.

---

# 14. Награды Траитора

Траитор получает XP/валюту за успешное выполнение своей задачи — точно так же, как награды из раздела 13, не влияя напрямую на исход матча:

* заставил игрока получить платное нарушение: +XP/валюта (чтобы не усложнять, любое нарушение считаем в плюс для треитора);
может быть позже: (* успешная ловушка: +XP/валюта;)

Можно добавить Траитору секретные задания на XP/валюту:

```text
Cause 3 players to violate the rule
```

или:

```text
Cause one player to violate the rule twice
```

Это заставляет Траитора активно играть, а не просто ждать — но сам исход матча решают условия победы из раздела 15, а не эти очки.

---

# 15. Условия победы

Матч — это противостояние **Investigators** (все, кроме Траитора) и **Траитора**. Есть два независимых пути к победе Investigators; выигрывает та сторона, чьё условие выполнилось первым.

## Условие A — Разгадывание (гонка)

Investigators побеждают, если разгадывают определённое количество правил за отведённое общее время раунда.

* Правило меняется сразу по факту разгадывания (раздел 4), а не по фиксированному таймеру — это делает гонку буквальной, а не ожиданием часов.
* Игрок, разгадавший правило — получает бонус и очки в счёт MVP (раздел 13).
* Если N разных игроков получили платное нарушение по текущему правилу — оно меняется без разгадывания, а общее время раунда сокращается (штраф Investigators, раздел 12).
* У Траитора есть способности, сокращающие оставшееся время раунда (раздел 9) — это увеличивает его шанс дотянуть до конца без того, чтобы Investigators успели разгадать нужное количество правил.
* Если время вышло, а нужное количество правил не разгадано — по умолчанию побеждает Траитор (время работает против Investigators, если они не успели).

## Условие B — Найти Траитора (голосование)

Реализовано без вызова голосования и пауз в игре:

* Каждый игрок (включая самого Траитора) выбирает одного подозреваемого. Выбор можно менять в любой момент матча.
* Голоса **видны всем публично** — кто за кого голосует, а не только тотал. Это единственная реальная улика против Траитора в игре: его паттерн голосования (не голосует за себя, переключается при давлении на него, подхватывает bandwagon на невиновного) — то, что игроки могут анализировать.
* Если стабильно (не мгновенно, чтобы не дёргать UI туда-сюда) сложилось большинство голосов на одном подозреваемом — всем игрокам показывается голосование **"Закончить игру досрочно?" (Да/Нет)**.
  * Если большинство ответило **Да** — матч заканчивается немедленно. Если подозреваемый большинства оказался настоящим Траитором — победа Investigators. Если нет — победа Траитора.
  * Если большинство ответило **Нет** — матч продолжается как обычно, условие A продолжает работать параллельно.
* Траитор голосует на равных условиях со всеми — это его дополнительный инструмент влияния (размыть консенсус, подставить другого), а не просто пассивное укрывательство.

# 16. Основной gameplay loop

Вся игра в итоге строится примерно так:

```text
Начало раунда
      ↓
Игроки получают задачи, у всех есть 1 бесплатное предупреждение на правило
      ↓
Секретное правило активно
      ↓
Игроки выполняют обычные действия / задачи / выбирают подозреваемого (можно менять)
      ↓
Кто-то нарушает последовательность → предупреждение или штраф
      ↓
Формируются гипотезы, игроки экспериментируют, наблюдают за другими
      ↓
Траитор провоцирует нарушения и/или голосует, размывая консенсус
      ↓
Правило разгадано → мгновенная смена + награда разгадавшему
      ИЛИ
N игроков нарушили без разгадывания → смена без разгадывания + сокращение времени раунда
      ↓
Параллельно: сложился консенсус по подозреваемому → голосование "закончить досрочно?"
      ↓
Матч заканчивается, когда: разгадано нужное число правил (Investigators) ИЛИ
              верно определён Траитор через досрочное завершение (Investigators) ИЛИ
              время вышло без того и другого / неверно определён Траитор (Траитор)
      ↓
Итоги матча: победившая сторона + MVP по XP/валюте за активность
```

# 17. Главный принцип дизайна

Игра должна быть построена вокруг ощущения:

> **"Я не знаю правило, но постепенно начинаю его понимать — и я не знаю, кто Траитор, но постепенно начинаю подозревать."**

Игрок должен постоянно задаваться вопросами:

* Почему я получил нарушение? Это было предупреждение или уже штраф?
* Что я сделал непосредственно перед этим?
* Что общего между двумя игроками, которые получили нарушение?
* Я правильно понял последовательность? Стоит ли попробовать её ещё раз, пока предупреждение не потрачено?
* Траитор специально заставил его это сделать?
* Кто вообще Траитор — и почему он голосует именно так?

При этом интерфейс не должен давать готовый ответ.

Он должен давать **достаточно информации для дедукции, но не настолько много, чтобы решение было очевидным**.

Именно поэтому:

* секрет — строгая последовательность из маленького, известного пула действий (Jump, Dash, Interact, Collect + уникальные карты); UI показывает только последнее действие;
* игрок должен сам запоминать последовательности; наблюдение за другими — важная часть игры;
* первое нарушение по каждому правилу бесплатно — это узаконенный, безопасный эксперимент;
* правило меняется по факту разгадывания, а не по таймеру — гонка буквальная;
* голоса за подозреваемого публичны — это единственная явная улика против Траитора, и она должна оставаться единственной, чтобы решение не было очевидным;
* Траитор — активная сторона: провоцирует нарушения, голосует, может сокращать время раунда — а не просто прячется;
* задачи — фон и прогрессия, а не путь к победе; победу определяют только два условия — разгадывание и раскрытие Траитора.
